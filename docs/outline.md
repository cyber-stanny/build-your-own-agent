# 课程大纲（设计稿）

> 状态：大纲已定，逐课细化中。本文件是课程的设计依据，正文写完后以各课 README 为准。

## 定位

**写给谁**：会写 JS/TS、调过 API，但没做过 agent 的开发者。自学为主，按顺序走完一条线性路线。

**学完能做到**：

1. 讲清 agent 的工作原理：loop、工具、context、记忆
2. 不用框架，手写一个能真正干活的 agent（约 150 行），接上真实模型跑通
3. 判断一个问题该用 workflow 还是 agent，并选对设计模式
4. 给 agent 接上知识库，并能用框架快速搭出一个
5. 知道怎么评测、调试 agent，清楚它会在哪里失败、花多少钱

**不覆盖**：生产部署、多租户、模型训练与微调。

## 设计原则

1. **真实模型优先，Mock 兜底**：第 1 课就配好 key；Mock 只服务 CI 和离线场景，输出显式标注 `[剧本]`。
2. **一个程序逐步长大**：第 1 部分是同一个 agent，每课加一层；每课一个快照目录，学员可以 diff 看到增量。
3. **每课一个问题、一个产出**：课题是一个问题；结尾有带验收标准的练习。
4. **真实实现放到最后**：正文不穿插「对应源码」表，集中到第 18 课。

概念分类以 Anthropic《[Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)》（2024-12）为一手来源：workflow 是「预先写好的代码路径编排 LLM 与工具」，agent 是「LLM 动态决定自己的流程和工具使用」。

「素材」列指重写前的旧版内容，已从工作区移除，需要参考时从这里取：本仓库提交 `e56af31`（`git show e56af31:<路径>`，路径如 `mini-agent/01-basic-chat/agent.mjs`、`patterns/coding-agent/`），表中「mini-agent」「patterns」「case-study」即其中同名目录。旧版只作素材，不照搬结构。

### 第 0 课 · Agent 到底是什么，什么时候不该用它

单次 LLM 调用、workflow、agent 三档对比；agent 用延迟和成本换灵活性，简单方案够用时不该上 agent。

### 第 1 部分 · 手写一个 Agent（核心）

| 课 | 核心问题 | 课后你手里有 | 素材 |
|---|---|---|---|
| 1 | 怎么和模型说话？ | 接通真实模型的 `chat()`；理解 messages 与角色 | mini-agent 01（改写） |
| 2 | 模型怎么「用工具」？ | 一次完整的 tool call：模型请求 → 你执行 → 结果回填 | mini-agent 03（改写） |
| 3 | 怎么让它一直干到做完？ | loop + 停止条件。**里程碑：能修失败测试的 coding agent** | mini-agent 02、patterns/coding-agent |
| 4 | 它为什么会忘、会撑爆？ | token 估算、工具结果截断、按完整轮次裁剪 | mini-agent 04（改写） |
| 5 | 怎么让它记住你？ | session（续上对话）与 memory（跨对话事实） | mini-agent 05/06（改写） |
| 6 | 怎么不让它闯祸？ | 工作目录边界、命令白名单、人工审批 | patterns/file-organizer、coding-agent（新写为主） |

### 第 2 部分 · 设计模式：选对结构

| 课 | 核心问题 | 素材 |
|---|---|---|
| 7 | 流程固定时，为什么不用 agent？ | 链式（content-creator）、路由（campus-assistant）、**并行（新写）** |
| 8 | 怎么让模型的输出能被程序直接用？ | 结构化输出 + 校验重试（resume-agent） |
| 9 | 怎么让它先想清楚、再检查自己？ | 规划（plan-execute）、评估-优化循环（reflection） |
| 10 | 一个 agent 不够时怎么办？ | 协调者-工人（multi-agent-demo）、sub-agent（mini-agent 08） |

### 第 3 部分 · 给 Agent 接上知识

| 课 | 核心问题 | 素材 |
