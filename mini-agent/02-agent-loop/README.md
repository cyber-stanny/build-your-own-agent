# 02 · Agent Loop —— 让模型持续干活

## 这个阶段是什么

一个 `for` 循环：反复调模型，直到模型宣布完成或打满轮数。这是 Agent 与「一问一答聊天机器人」的本质区别。

## 相比上一阶段增加了什么

| 增加 | 为什么 |
|---|---|
| `MAX_TURNS` 上限 | 防死循环的安全阀（原项目默认 32） |
| 每轮发言 push 回 messages | 模型下一轮要看到自己的进度，否则原地打转 |
| 停止条件判定 | 本阶段用 `<DONE>` 文本标记模拟；真实项目用「是否要求调工具」 |
| 三个停止条件 | 模型完成 / 打满轮数 /（下一阶段：操作被拒绝） |

## 运行

```bash
cd mini-agent/02-agent-loop
node agent.mjs "从 3 倒数数到 1，每数一个数停一下"
```

## 示例输出（mock 模式）

```
── 第 1 轮（携带 2 条历史）──
模型: 正在处理第 1 步：3
── 第 2 轮（携带 4 条历史）──
模型: 正在处理第 2 步：2
── 第 3 轮（携带 6 条历史）──
模型: 最后一步：1，任务完成 <DONE>

最终结果: 最后一步：1，任务完成
```

注意每轮「携带 N 条历史」在增长——这就是多轮的本质：**历史累积在同一数组里**。
